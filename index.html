How a request moves

From a voice note on my phone to a finished, tracked result, with anything I would regret waiting for my approval: sends, deletes and public pushes.

01 Input

Any-Device Ingest

I dictate on my phone or Mac (FreeFlow, Dictate) and send it on Discord or Telegram.

02 Router

Central Triage & Router

A router agent reads the request, checks which domain owns it, and files a kanban task for the right specialist.

03 Agents

10 domain agents

Domain agents run around the clock on an Azure server, each with its own workspace, memory and tools.

04 Models

Model choice

Harder tasks go to stronger models; routine ones go to faster, cheaper ones. Plain scripts run first.

05 waits for me

The Human Gate

Pushes, emails, deletions and ledger writes stop here.

06 Output

Delivery & Ledger Sync

Results land in Google Tasks, GitHub, the Firefly III ledger, or a chat message to me.

Six agent systems, one person signing off

I run a personal multi-agent platform on open-source Hermes Agent. I did not write Hermes. My part is the design: which agent owns what, how work moves between them, and where it has to stop for me.

A router and 10 domain agents each own one area. Work moves on kanban cards, from an orchestrator to a worker and then to a review gate.
