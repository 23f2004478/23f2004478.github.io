The Scoping Challenge in Enterprise Banking

Enterprise quality assurance scoping across commercial banking applications presents unique complexity. Large institutions operate dozens of interconnected systems spanning core banking, loan origination, loan management, payment gateways, and regulatory reporting.

Historically, estimating QA effort relied on disparate spreadsheets maintained by separate project leads. This created three core operational bottlenecks:

  • Fragmented calculation formulas: Different teams calculated test effort using varying multiplier assumptions, leading to wide discrepancies for identical banking workflows.
  • Absence of historical variance tracking: Organizations lacked a structured repository comparing upfront person-day estimates against actual delivery effort across application domains.
  • Manual test case ingestion: Thousands of QA test cases were maintained in loosely formatted spreadsheets, requiring extensive manual cleanup before migration to test management systems.

Architecture and System Delivery

To establish a consistent, auditable estimation baseline, I engineered a unified monorepo platform designed to standardize complexity scoring and track estimation variance over time.

1. Root Mean Square (RMS) Complexity Scoring Engine

Designed a mathematical scoring model that rolls up 349 banking processes across 56 functional modules and 11 banking domains. The engine calculates an RMS complexity score incorporating risk floors for regulatory compliance, data sensitivity, and third-party integration density.

2. Full-Stack Monorepo Architecture

Developed the complete platform solo using an AI-orchestrated workflow, committing 144 commits in 7 weeks across 10 backend feature modules:

  • Backend: NestJS application structured with clean separation across modules, controllers, services, and TypeORM entity definitions backed by PostgreSQL.
  • Calculation Engines: Authored 2 deterministic TypeScript calculation engines totaling 1,027 lines of verified code.
  • Unit Test Coverage: Implemented 136 unit tests (68 testing core mathematical functions and 68 validating exact parity with legacy spreadsheet models).
  • Frontend: React single-page application providing domain navigation, process parameter configuration, and variance analytics dashboards.

3. Historical Tracking & MAPE Scoring

Built a full-stack data pipeline capturing 38-field estimate-versus-actual records. The system records post-engagement outcomes, scoring Mean Absolute Percentage Error (MAPE) and variance metrics across application categories to refine future baselines.

4. Automated Push-to-Deploy CI/CD Pipeline

Configured a zero-downtime deployment pipeline to an AWS EC2 instance. A 5-stage push-to-deploy git hook automated branch verification, monorepo dependency builds, database migration runs, PM2 process reloading, and Nginx reverse-proxy configuration.

5. Azure DevOps Test Case Standardization Tooling

Engineered Python data transformation scripts that reshaped 18,456 rows across 61 bank QA workbooks, standardizing schemas for bulk upload into Azure DevOps test suites.

6. Machine Learning Scoping Specification (PRD)

Authored a comprehensive 1,147-line Product Requirement Document (PRD) specifying 20 functional requirements and 6 regression targets across 10 engineered features for future statistical effort estimation.

Key Engineering Takeaways

  • Parity testing before migration: When migrating business calculations from spreadsheets to code, writing dual-suite unit tests against known spreadsheet inputs guarantees zero silent calculation drift.
  • Deterministic rules precede machine learning: Structured mathematical baselines provide immediate transparency and auditable data collection required for future statistical modeling.
  • Automation accelerates scoping cycles: Eliminating manual spreadsheet transformation through scripted pipelines allows engineering teams to focus on core system verification.
