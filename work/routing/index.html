Model routing and tiered compute: local gateway with fallback resilience

One gateway on my server in front of several model accounts, with backup models when one fails, and three effort levels for different kinds of work. Plain scripts handle deterministic computation before any model is invoked.

Gateway
9Router gateway on my server
Routing Strategy
Backup models · 3 main effort levels (medium, high, max)
Core Invariant
Plain scripts run before any AI model

Problem

Directly binding agent workflows to a single AI provider causes brittle failures when rate limits or upstream outages occur. Furthermore, sending basic data extraction or mechanical formatting tasks to expensive models wastes tokens and increases latency.

What I Built

  • 9Router gateway: A small service on my server that sits between most agents and the AI providers and moves a request to a backup model when one fails. Claude models are called directly.
  • Tiered Compute Offload (Fable): When a task requires exhaustive multi-file architectural planning, design system direction, or deep fact audits, work offloads to our maximum-tier reasoning harness (Fable) to produce a rigorous, executable specification before any code is written.
  • Deterministic First Rule: Exact computations (mathematical formulas, file system queries, regex extractions) must execute in native Python or Bash before passing structured context to an LLM.

How the Gateway Pools Models

  • 9Router pooling: 9Router runs on the server itself and gives most agents one address for many models. Behind it sits a pool of providers; if one provider rate-limits or fails, the request moves to the next one, with Gemini Flash as the default backup.
  • Cost tiering: Cheap, fast models take bulk work; the expensive model is reserved for steps where an error is costly. Plain scripts run first, so many tasks never reach a model. I state no cost figures here.

Dynamic Routing and Complexity Tiering

Tasks are routed dynamically across models based on task complexity, speed, and cost efficiency: Gemini Flash handles high-volume sweeps and lightweight tools, Claude Sonnet handles deterministic code generation and test suites, and Claude Opus handles deep multi-file reasoning and architectural verification.

Tiered Compute Offload (Fable): When a task requires exhaustive multi-file architectural planning, design system direction, or deep fact audits, work offloads to our maximum-tier reasoning harness (Fable) to produce a rigorous, executable specification before any code is written.

  • Gemini Flash: High-throughput sweeps, reading, scraping, telemetry, and lightweight tool handling.
  • Claude Sonnet: Deterministic code generation, test suites, refactoring, and generator scripts.
  • Claude Opus: Deep multi-file reasoning, verification gates, and quality audits.
  • Fable: Architectural planning, design system direction, and exhaustive fact audits.

Outcome

When a provider hits a rate limit, work moves to a backup model instead of stopping. Plain scripts do the bulk filtering on the server, so the models get less to read and the numbers come out the same every time.

Limits

Switching to a backup model can make a reply slower, so each call needs a sensible time limit.
