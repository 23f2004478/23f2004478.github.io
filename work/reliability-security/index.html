The Reliability & Security Challenge

Running a continuous multi-agent system in production creates serious operational vulnerabilities if resilience and security are not treated as core architectural requirements:

  • Single Point of Server Failure: Cloud instances can experience hardware crashes, kernel panics, or accidental corruption. Rebuilding an entire multi-agent runtime from scratch without automated recovery takes days of manual reconfiguration.
  • Credential Exposure & Secret Exfiltration: Agent execution loops running arbitrary shell commands or processing unstructured external data must never be allowed to read, print, or transmit private API keys or SSH credentials into chat context.
  • Configuration & State Drift: Over time, dangling symlinks, corrupted SQLite transaction locks, stale temporary workspaces, and untracked environment variables silently break scheduled workflows.
  • Unverified Context Mutations: Modifying operational rules or prompt files without structural validation can introduce formatting bugs that break downstream parser logic.

System Architecture

The platform implements an end-to-end security and disaster recovery lifecycle, combining automated health daemons, restricted secrets handling, encrypted offsite capsules, and a one-click bare-metal restoration script.

Text description of architecture: The security and reliability architecture combines continuous governance via hourly medic audits and md_guard.py context validation with locked-down secrets stored in permission-isolated vault files. State is automatically archived into GPG-encrypted backup capsules and mirrored offsite to private GitHub Releases. In the event of server loss, a deterministic restore.sh script reconstructs all 12 profiles, systemd services, and databases on a fresh VPS in minutes.

1. Encrypted Backup Capsules & Offsite Mirroring

To eliminate reliance on cloud provider snapshots and ensure portable disaster recovery:

  • A nightly cron workflow gathers all active configuration files, SQLite task databases, profile memory directories, and custom skill modules.
  • The archive is encrypted locally using strong symmetric GPG encryption with passphrases managed outside the runtime.
  • The encrypted capsule is automatically pushed offsite to a private GitHub Releases repository via the GitHub CLI API.
  • Old release capsules are automatically rotated and pruned to maintain predictable storage footprints.

2. Automated Bare-Metal Disaster Recovery (restore.sh)

A resilient backup is only as good as its restore procedure. The estate maintains a deterministic, end-to-end restoration script:

  • One-Command Rebuild: When executed on a clean Linux host (Ubuntu 24.04 LTS), restore.sh fetches the latest encrypted capsule from GitHub Releases, decrypts the payload, provisions required system packages, and unpacks the 12 profile environments.
  • Service Re-registration: Automatically configures systemd daemons, loopback proxy endpoints, and cron jobs, bringing the full multi-agent estate back into operation in under 10 minutes.

3. Continuous Governance & Medic Drift Audits

The platform runs an active health monitor daemon (Medic) configured to run hourly checks:

  • Service Health & Drift: Verifies that all 31 systemd units and cron jobs are active, healthy, and synchronized with repository manifests.
  • Database Integrity: Inspects SQLite task databases for lock contention, orphaned jobs, or unclosed transactions.
  • Disk & Workspace Cleanup: Identifies bloated scratch directories and generates cleanup recommendations for the Janitor daemon.

4. Locked-Down Secrets & Context Guardrails

To ensure total defense against prompt injection and credential leaks:

  • Locked-Down Secrets Handling: API tokens, private SSH keys, and OAuth credentials reside exclusively in filesystem-restricted files with locked-down access permissions.
  • Zero Secrets in Chat: Credentials are bound to local proxy daemons or origin-bound autofill tools, ensuring that no sensitive secrets are ever present in model context windows or conversation logs.
  • Context Guard Validation (md_guard.py): A pre-commit validation hook audits all markdown context files, verifying rule adherence, formatting constraints, and prohibiting unapproved modifications.

Human Approval Gates & Safety Controls

  • Disaster Recovery Execution: Executing bare-metal restores and major state rollbacks requires explicit operator initiation.
  • Destructive Pruning Gates: Janitor proposals for deleting old workspace directories require human review before file deletion.
  • Credential Management: Secret rotations and vault modifications are strictly performed by the human operator.
