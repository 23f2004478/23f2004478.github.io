The Multi-Domain Operational Challenge

Running autonomous AI agents across divergent workflows presents severe architectural challenges when scaling beyond a single assistant:

  • Context pollution across domains: Giving a single agent access to personal finance, academic papers, consulting projects, and system infrastructure causes prompt degradation, tool misuse, and accidental data exposure across contexts.
  • Runaway execution and tool loops: Autonomous agents running unattended can get trapped in repetitive reasoning loops or trigger unverified external side effects without human oversight.
  • State synchronization and handoffs: Multi-step deliverables require clean decoupling between high-level decomposition and specialized implementation, with verified artifacts handed off across worker agents.
  • Disaster recovery and security: Credentials and long-term memory must remain protected against leakages, with complete automated estate recovery from bare-metal backups.

System Architecture

The platform was initialized on September 11, 2026 within a local macOS Lima VM, and migrated on September 20, 2026 to a dedicated cloud VPS running Ubuntu 24.04 with systemd services. The architecture decouples ingress, orchestration, execution, model routing, and governance into isolated layers.

Text description of architecture: Telegram and Discord channels connect to specific agent profiles via a multi-bot gateway. The Default Orchestrator triages requests, decomposes tasks, and logs them to a shared SQLite Kanban board. 12 domain profiles execute tasks within isolated directory environments. High-reasoning subtasks route through a local 9Router proxy with automatic fallback across compute tiers. Continuous governance is maintained through hourly medic drift audits, janitor cleanup proposals, 0600 vault secrets, and encrypted offsite backups.

1. Multi-Profile Domain Isolation

Rather than running a monolithic prompt, the estate partitions operational concerns across 12 domain profiles with mutually exclusive context boundaries:

  • Domain Lanes: Distinct profiles dedicated to career tracking, academic coursework, personal finance ingestion, server infrastructure, market research, consulting delivery, and daily personal operations.
  • Independent Memory & State: Each profile maintains its own dedicated workspace, personal notes, and tool permissions, preventing cross-domain context contamination.
  • Procedural Skills: Profiles dynamically load relevant procedures from a catalog of 341 skill files (combining custom scripts and third-party tools) rather than cluttering system prompts.

2. Asynchronous Kanban Orchestration

Cross-agent collaboration runs asynchronously over a central SQLite-backed Kanban board:

  • The orchestrator profile decomposes high-level goals into scoped child cards with explicit dependency chains.
  • Domain workers claim ready tasks, log heartbeats during long operations, and transition tasks to structured review states upon completion.
  • Structured handoffs enforce machine-readable metadata and human-readable summaries before downstream promotion.

3. Tiered Compute Routing via Loopback Proxy

To balance latency, capability, and execution cost, local tool calls connect through 9Router, an intelligent loopback model proxy running as a local service:

  • Tiered Offload: Routine mechanical automation executes on lightweight models, while complex system design, deep document analysis, and long code generation automatically offload to high and maximum reasoning tiers.
  • Graceful Fallback: Automatic failover prevents pipeline stalls when upstream provider endpoints experience transient rate limits or outages.

4. Governance, Continuous Auditing, and Disaster Recovery

Unattended automation requires continuous health monitoring and zero-loss disaster recovery:

  • Hourly Medic Daemon: A dedicated health-monitor profile runs hourly audits checking for configuration drift, orphaned tasks, tool permission mismatches, and route integrity.
  • Janitor Cleanup Proposals: Stale temporary files and scratch workspaces are identified automatically; actual file deletions require explicit human confirmation.
  • Encrypted Backup Capsules: Production state, configuration files, and procedural databases are packaged into encrypted capsules and pushed offsite to private GitHub Releases.
  • Automated Disaster Recovery: A verified restore script (restore.sh) allows complete bare-metal recovery of the entire 12-profile estate onto a fresh Linux VPS in minutes.

Strict Operating Rules & Safety Guardrails

The entire platform operates under non-negotiable safety invariants enforced in software:

  • Human-in-the-loop gates for side effects: The platform is strictly prohibited from sending outbound emails, publishing code to main branches, executing financial payments, or deleting persistent files without explicit human sign-off.
  • Zero secrets in conversation: API keys and credentials are stored in 0600 permission vault files. Origin-bound password autofill prevents credential exposure in model contexts or chat transcripts.
  • Isolated execution workspaces: Multi-step jobs execute inside ephemeral scratch directories, preventing accidental modification of core system configurations.
  • Real-world artifact generation: As a concrete example of self-directed platform delivery, this website plan was produced by the high reasoning tier and executed across kanban task handoffs by the consulting profile.
