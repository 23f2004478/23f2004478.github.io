Multi-Agent Operations Platform

Designed and operating a multi-agent estate on the open-source Hermes Agent framework across 12 domain profiles, 31 scheduled workflows, loopback model proxying, and kanban task orchestration with human approval gates.

Architecture Diagram

Problem Statement & Design Goals

Managing multi-faceted academic, research, software consulting, and personal finance workflows with general-purpose AI chat leads to context contamination, drift, and lack of reproducible execution. The goal was to engineer a robust, self-documenting multi-agent operating environment hosted on private cloud infrastructure with strictly separated domains, auditable telemetry, and human approval gates on all real-world side effects.

Architecture & Platform Separation

The platform is organized into three distinct operational layers:

  1. Messaging Ingress & Routing Gateway: Incoming events from Telegram and Discord channels are routed directly to specific profile listeners based on domain boundaries.
  2. Domain Profile Partitioning: 12 dedicated profiles operate with isolated configurations, cron schedules, and procedural memory (e.g., finance, infra, academic-researcher, workhorse).
  3. Supervisory Health & Governance: The medic profile audits the estate hourly for configuration drift and skill scope integrity, while janitor manages temporary file pruning under explicit human confirmation.

Strict Operating Rules & Safety Guardrails

The entire platform operates under non-negotiable safety invariants enforced in software:

  • Human-in-the-loop gates for side effects: The platform is strictly prohibited from sending outbound emails, publishing code to main branches, executing financial payments, or deleting persistent files without explicit human sign-off.
  • Zero secrets in conversation: API keys and credentials are stored in filesystem-restricted vault files. Origin-bound password autofill prevents credential exposure in model contexts or chat transcripts.
  • Isolated execution workspaces: Multi-step jobs execute inside ephemeral scratch directories, preventing accidental modification of core system configurations.
  • Real-world artifact generation: As a concrete example of platform delivery, this website redesign was planned by the high reasoning tier and executed across kanban task handoffs by the consulting profile.
