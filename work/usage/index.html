List price vs subscription

At published list prices this volume comes to about $5,013.54 USD: $3,129.10 for proxied calls as computed by the proxy, and $1,884.44 as estimated by my runtime for direct Claude calls. I did not pay that figure. The direct Claude calls run on a flat subscription. I do not publish my bill, so read the list price as the honest upper bound and the subscription as the reason a personal system at this volume is affordable.

Why the cache rate matters

An agent resends its system prompt, its tools and the conversation so far on every call. Without a prompt cache, every one of those tokens is read fresh at full price and full latency. A hit rate near 92.1% means almost all of that context was served from a stored prefix. It is the single number that decides whether a long running agent is affordable, and it is a design outcome, not luck: stable prompt prefixes, tool definitions that do not change between calls, and context that grows by appending rather than rewriting.

What this tells you

The system is in daily use. The grid has no long gaps; this is not a demo run once for a screenshot.

Most tokens are context, not writing. Less than one token in a hundred is generated. That is what a tool using agent looks like: it reads a lot, decides, acts, and says little.

I pick models by cost and fit, not by brand. Cheap fast models carry the volume; expensive models get the judgement calls. The family table shows the ratio.

The numbers are reproducible. Every figure on this page comes from one JSON file rebuilt six hourly from the proxy database, my runtime's state database and the CLI transcripts, with the formulas in the note below. The file is public at /work/usage/data.json.

How I count

This ledger counts only traffic through my proxy; the typed decision layer runs on its own service and is reported on Fast decisions.

Four categories, each token counted once: fresh input, cached read, cache write, output. Reasoning tokens are a subset of output and are shown only as "of which". Total is the sum of the four.

Proxy calls (OpenAI style): fresh input is prompt tokens minus cached tokens, cached read is cached tokens, output is completion tokens. This API does not report cache writes or reasoning, so those read n/r.

Direct calls (Anthropic style): fresh input is input tokens, cached read is cache read tokens, cache write is cache creation tokens, output is output tokens, and reasoning is reported separately inside output.

Claude Code: the same Anthropic style fields read from the transcript files, with duplicate message ids removed.

Cache hit rate is cached read divided by all input, where all input is fresh plus cached read plus cache write. Model names are grouped into families. List prices are the per token prices published by each provider as applied by the proxy or estimated by my runtime; they are not invoices. The window starts on 2026-09-13, the first day any source logged tokens.

Accounting invariants and verification

The numbers on this page are computed deterministically during every site build. The build script queries the live databases and asserts twelve mathematical invariants before outputting static HTML:

  1. Exact integer sum parity: The four components (fresh input, cache read, cache creation, output) sum exactly to the grand total across every source, model family, and daily record.
  2. Zero double counting: Hermes direct Claude accounting includes only direct subscription rows, excluding proxy routes to prevent double counting.
  3. Contiguous date continuity: The daily calendar grid contains zero missing dates between the tracking start date and today.
  4. Non-negative fresh input: Every proxy daily record satisfies prompt tokens ≥ cached tokens, guaranteeing non-negative fresh input.
  5. Reasoning containment: Reasoning tokens are strictly contained within output tokens on every reporting provider.
  6. Telemetry capability reporting: Providers that do not report cache creation or reasoning are explicitly flagged with False capabilities rather than zero.
  7. Family classification exhaustiveness: Every encountered model is mapped to a named family without version strings or unclassified fallbacks.
  8. Calendar day alignment: All timestamps from 9router, Hermes, and Claude Code are normalized to Asia/Kolkata (IST) calendar boundaries.
  9. Single partial day: Exactly one daily record (today) is flagged as partial.
  10. Reproducible data artifact: The complete token dataset is published as machine-readable JSON at /work/usage/data.json.
  11. Cost estimation boundaries: Dollar figures represent published list prices rather than subscription invoices.
  12. Number refresh stability: The page template is static and values are injected deterministically to ensure automated refreshes change digits only.

Local probe: Run python3 scripts/gen_metrics.py to recompute metrics.json directly from 9router, Hermes state.db, and Claude Code transcripts.
