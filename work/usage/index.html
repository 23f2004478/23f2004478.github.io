The four components

Tokens logged by language models belong to four distinct operational categories. Over 99% of token volume represents context read by the models rather than new text written. Prompt caching serves most of this context from memory at a fraction of standard input pricing.

Accounting invariants and verification

The numbers on this page are computed deterministically during every site build. The build script queries the live databases and asserts twelve mathematical invariants before outputting static HTML:

  1. Exact integer sum parity: The four components (fresh input, cache read, cache creation, output) sum exactly to the grand total across every source, model family, and daily record.
  2. Zero double counting: Hermes direct Claude accounting includes only direct subscription rows, excluding proxy routes to prevent double counting.
  3. Contiguous date continuity: The daily calendar grid contains zero missing dates between the tracking start date and today.
  4. List price estimation: Dollar equivalents are computed using published per-token list prices to measure workload value independently of subscription billing.

Local probe: Run python3 scripts/gen_metrics.py to recompute metrics.json directly from 9router, Hermes state.db, and Claude Code transcripts.
