Work

Multi-agent operations platform: MECE 12-profile estate with kanban hand-offs

In plain terms: a set of AI assistants I run for my own work, one per area (finance, coursework, job applications, server upkeep, social posts). Each stays inside its own area, they pass tasks to each other through a shared board, and cleanup and site deploys wait for my approval.

A personal multi-agent platform operating 12 profiles (a routing hub plus 11 domain profiles), Discord/Telegram channel routing, and a kanban board for orchestrator-to-worker hand-offs. Private system; architecture shown here.

Built on Hermes Agent (open source, Nous Research). I did not write Hermes; many skills are third-party. I designed the partitioning, routing, guardrails, and the scripts that hold them together.

Context

Running an AI agent without partitioning means one profile accumulates all context: finance data next to resume drafts next to system administration. The profiles bleed into each other and the agent's instructions become contradictory. The fix is mutually exclusive, collectively exhaustive (MECE) partitioning: each profile owns one domain, reads only its own workspace, and cannot touch another domain's files.

The secondary problem is handoff. An orchestrator that writes a plan and executes it in the same session cannot be reviewed or rejected in the middle. The kanban board provides the boundary: the orchestrator creates a card, assigns it to the right profile, and stops. The worker picks it up, implements, and requests review. The reviewer signs off. No step can skip the gate.
