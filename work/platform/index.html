Multi-agent operations platform: MECE 12-agent estate with human review gates

Twelve agents that hand work to each other on kanban cards, with a review gate before anything risky. Built on open-source Hermes Agent.

Built on Hermes Agent (open source, Nous Research). Private system; architecture and verified telemetry shown here.

Problem and Motivation

Running multi-domain automation through a single monolithic agent leads to prompt pollution, inconsistent tool permissions, and unpredictable actions. An agent drafting an email should not have access to production deployment keys, and a financial parser should not manage social media drafts.

What I Built

I structured an estate partitioned into 12 Mutually Exclusive, Collectively Exhaustive (MECE) agents. Each agent operates with scoped permissions, its own persistent memory, and dedicated skill sets:

  • Central Router: Receives inbound messages from Discord or Telegram, classifies intent, and delegates tasks to domain agents.
  • Domain Agents: 11 specialized agents (academic researcher, candidate, exam helper, finance, infra, janitor, medic, personal ops, socials, workhorse, plus one private-scope agent not described here).
  • Kanban Coordination: Complex tasks are decomposed into structured kanban cards containing objective, context, and acceptance criteria.
  • Human Review Gate: Irreversible side effects (sending communications, modifying financial records, merging pull requests) pause at review gates until I sign off.
  • Continuous Maintenance: A medic agent audits configuration drift hourly; a janitor agent flags cleanup opportunities and acts only upon approval.

How a Request Moves

I dictate instructions using FreeFlow on Mac or Dictate on Android, read the transcript, and send it via messaging gateways. Built-in voice plugins are skipped so I can read what got written before an agent acts on it.

Multi-agent execution workflow
Stage Actor Responsibility Gating
1. Ingestion Human Dictate, verify text, and send to gateway channel Human input
2. Gateway 9Router Routes inbound webhook to agent runtime Automated
3. Router Agent default Classifies request and spawns task card Automated
4. Task Card Kanban Engine Dispatches card to assigned domain agent Automated
5. Execution Domain Worker Executes read-only steps and drafts deliverables Automated
6. Review Gate Human Inspects diff/artifact and approves execution Human sign-off
7. Completion Domain Worker Applies approved change and closes task Automated after gate
8. Output Sync Google Tasks / SQLite Actionables needing human attention sync to Google Tasks Automated

Hosting and Access

The runtime moved from a MacBook Linux VM to an Azure cloud VPS (Ubuntu 24.04, systemd services) on 20 Sep 2026, so the agents run 24/7 without my laptop being on.

  • Azure Cloud VPS: Every agent runs here as a systemd-managed service. The model gateway and provider sync restart on their own after a reboot.
  • Tailscale mesh: Tailscale, a WireGuard-based private network, links my devices to the server over encrypted tunnels.
  • Termius mobile access: From my phone I open an SSH session in Termius over that mesh to check or restart a service without a laptop.
  • Workspace isolation: Each agent has its own working directory, persistent memory, scoped tools and skills. Each domain keeps its own data in its own workspace.

Verified Outcome

The platform runs 39 enabled recurring scheduled jobs across 12 agents. This entire website was designed, built, fact-audited, and verified through this exact multi-agent kanban pipeline.
